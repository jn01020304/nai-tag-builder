# n차 의사결정 과정 교정 사항

## 배경
코드베이스 정비를 위해 n차 의사결정 프로세스를 코드 작업에 처음 적용. 0차에서 여러 차례 교정을 거쳐 올바른 접근법을 확립.

## 교정 1: 탐색은 기술 감사가 아니다
잘못된 접근: 코드를 스캔하고 "6개 영역"을 나열하고 "어디까지 할 건가요?" 질문.
올바른 접근: 사용자의 의도와 고충에서 출발. 기존 계획(ARCHITECTURE.md R1~R5, HANDOFF)을 먼저 읽고 입력으로 삼는다. 사용자의 비전을 끌어내는 것이 목적이지, AI의 기술적 발견물을 나열하는 것이 아님.

## 교정 2: 잠정 결정을 내려라
잘못된 접근: "이것은 ~인가? 저것은 ~인가?" 형태의 열린 질문 4개를 사용자에게 던짐.
올바른 접근: 각 항목에 대해 잠정 결정(tentative decision)을 내리고 근거를 제시. 사용자는 틀린 부분만 교정. 의사결정 라운드의 산출물은 "질문 목록"이 아니라 "결정 + 근거".

## 교정 3: 간단한 조사는 즉시 실행
잘못된 접근: "10개 컴포넌트 중 어느 것이 theme 전역변수를 직접 참조하는지 미조사" → 심화로 이월.
올바른 접근: grep 한 번이면 끝나는 조사를 심화로 미루지 않는다. 30초 안에 해결 가능한 것은 즉시 실행. 심화에는 진짜 깊은 조사(파급 범위 실측, 마이그레이션 전략 비교 등)만 남긴다.

## 교정 4: "진행할까요?" 금지
잘못된 접근: 사용자가 "다음 단계로 진행해"라고 지시하고, AI도 "다음은 1차 탐색 실행"이라고 판단한 뒤, "1차 탐색을 바로 진행할까요?"라고 재확인.
올바른 접근: 방향이 확립되었으면 즉시 실행. 불필요한 확인 질문은 "결정을 내려라"는 피드백의 약한 변형에 불과.

## 적용 범위
이 교정 사항은 nai-tag-builder 프로젝트뿐 아니라, n차 의사결정 프로세스를 사용하는 모든 코드 작업에 적용.
