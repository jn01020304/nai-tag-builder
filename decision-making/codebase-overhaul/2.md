# 2차: 심화 — 미결 3건 해소

## R4: 마이그레이션 전략 확정

### 조사 결과

Dexie의 `version().stores()`는 인덱스만 관리하며, 기존 레코드의 데이터를 자동 변환하지 않는다. PresetEntry.settings와 StateEntry.stateJson은 JSON 문자열이므로, 필드 추가 시 기존 문자열에는 새 필드가 없다. `JSON.parse()` 후 `as MetadataState` 타입 단언은 런타임에 아무것도 강제하지 않아 누락 필드가 `undefined`로 남는다.

기존 코드에 `migrateOldLocalStorage()` 선례가 있음 — localStorage → IndexedDB 일회성 마이그레이션.

선택지 2가지:
- Dexie `.upgrade()` 훅: DB open 시 일괄 변환. 영구 수정. DB 버전 범프 필요.
- 로드 타임 정규화: `{ ...DEFAULT_STATE, ...parsed }`. 매 로드마다 적용. DB 변경 없음.

### 확정 결정

로드 타임 정규화 채택.

이유:
- 기존 `migrateOldLocalStorage()` 패턴과 일관성
- DB 버전 범프 불필요 (위험 감소)
- D2 구조 분리 시에도 같은 패턴으로 대응 가능 (정규화 함수만 교체)

구현:
```typescript
function normalizeMetadataState(partial: any): MetadataState {
  return { ...DEFAULT_STATE, ...partial };
}
```

적용 위치:
- presetStorage.ts — loadPresets(), getPresetById()에서 JSON.parse 직후
- useMetadataState.ts — DB 로드 시 JSON.parse 직후

appState "current" 엔트리도 동일하게 처리.

## R1: 마이그레이션 범위 확정

### 분석

코드 실측 결과:
- 9개 컴포넌트가 `theme` 전역 import → 전부 inline 사용(`style={{ color: theme.text }}`), useDynamicTheme 재할당 + Context cascade로 정상 동작.
- 실제 버그는 모듈 레벨 정적 상수 3개뿐.
- 9개 전체 → useTheme() 마이그레이션은 React 안티패턴 제거 (코드 품질). 현재 동작을 깨뜨리지도, 로드맵을 차단하지도 않음.

### 확정 결정

이번 정비: 정적 상수 3개만 수정 (컴포넌트 함수 내부로 이동).
9개 전체 useTheme() 마이그레이션은 이번 정비 범위 밖. 향후 확장으로 분리.

이유:
- 사용자 동기("디버깅 난이도 감소" + "로드맵 기반")에 9개 전체 마이그레이션은 기여하지 않음.
- 3개 수정은 2분, 9개 전체는 9파일 수정 + 테마 글로벌 제거 + useDynamicTheme 리팩토링. 비용 대비 효과 불일치.
