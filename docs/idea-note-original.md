# Danbooru Tag 기반 NovelAI 프롬프트 빌더 — 아이디어 노트

## 핵심 철학 3가지

### 프롬을 쉽게 작성한다
자연어 → 태그 변환, 시각적 가중치 편집

### 이미지를 자동으로 생성한다
API 연동, 자동 추천, 배치 생성

### 프롬과 이미지를 편하게 관리한다
선별 · 비교 · 보정 · 동기화

## 기능 아이디어 모음

### 철학 1 — 프롬을 쉽게 작성한다
- 자연어 → 태그 변환 AI: 사용자가 자연어로 입력하면 Danbooru 태그 + 가중치로 자동 변환
- 태그 가중치 막대그래프 UI: 양수는 위, 음수는 아래로 표현하는 막대그래프: 터치/슬라이더로 가중치 직접 조절
- 태그 칩(Chip) 드래그 앤 드롭: 태그 순서를 손가락으로 재배치
- 프롬프트 재조합 AI: 기존에 모아둔 프롬들을 AI가 섞어서 새 조합 제안
- 부정 프롬프트 템플릿: 단골 네거티브 세트를 토글 스위치로 켜고 끄기
- 레퍼런스 시각화: 작가별 예시 이미지를 태그 아래에 표시

### 철학 2 — 이미지를 자동으로 생성한다
- NovelAI API 연동: API 키로 직접 이미지 생성 호출
- AI 보고서 기반 자동 추천: AI가 사용 패턴을 보고 프롬프트 구성을 추천
- 만화 / 스토리보드 생성 모드: 자연어 시나리오 → 여러 컷 프롬프트를 자동 생성

### 철학 3 — 프롬과 이미지를 편하게 관리한다
- 이미지 오류 탐지 ("엑스레이 스캔"): 생성 직후 비전 AI가 찐빠 부위를 히트맵으로 표시
- 이미지 선별 ("틴더식 스와이프"): 우 스와이프 → 저장, 좌 → 삭제, 상 → 수술실(인페인팅) 전송: 평가 기준: 손발 구조, 의상, 눈동자/머리카락 색상 일관성
- 반자동 인페인팅 보조 ("탭-투-마스크"): 찐빠 부위를 터치 → AI가 영역 자동 인식 → 마스킹 → 수정 태그 추천: 인페인팅으로 수습 가능한 이미지는 AI가 자동 판별
- 이미지 비교 "딸깍": 생성된 이미지를 나란히 비교하는 UI
- 프롬프트 히스토리 보관함: 과거 프롬을 검색 · 재활용

## 모바일 UX 아이디어

### 화면 한계 극복
- 스마트 탭 자동 분류 — [인물], [배경], [구도] 등 카테고리별 태그 그룹화로 스크롤 지옥 방지
- 바텀 시트 슬라이더 — 태그 터치 시 하단에서 가중치 조절 팝업 → 화면 복잡도 감소

### 제스처 숏컷
- 3손가락 탭 → 즉시 생성
- 2손가락 더블 탭 → 이미지 비교
- 3손가락 스와이프 다운 → 초기화
- ⚠️ iOS/Android 시스템 제스처와 충돌 가능성 검증 필요

## 드레일 (잊으면 안 되는 것들)
- 모바일 화면 한계: 태그 30~50개 넘으면 스크롤 지옥. 탭 분류 + 바텀시트로 해결 시도
- 비전 AI 비용: 찐빠 선별·자동 마스킹은 서버 비용 + 개발 난이도 높음
- 대기 시간 (Latency): 변환·생성 10~30초 동안 이탈률 관리 필요
- API 키 보안: 유료 키를 클라이언트에서 어떻게 안전하게 보관할 것인가
- 스토어 심사 & NSFW: 앱스토어 배포 시 성인물 관련 제재 리스크

## 기술 메모
- 데이터 구조 (태그 객체): `{ id, keyword, category, weight, isEnabled, isNegative }`
- 프롬프트 컴파일러: 객체 배열 → NovelAI 문법 (`{ }`, `[ ]`) 최종 문자열 조립
- 배포 방식: GitHub 호스팅 스크립트 + 북마크릿 로딩
- 동기화: DB Import/Export 기본 지원 → 추후 서버리스 DB (Firebase/Supabase) + Google 로그인으로 기기 간 동기화

## 개발 순서 감각 (대략적 흐름)

> 엄밀한 로드맵이 아니라, "대체로 이 순서가 자연스럽다"는 감각 메모입니다.

1. 1순위 — 기초 토대
   - DB 구조, 디자인 시스템, 코어 API 연동 테스트
2. 2순위 — 핵심 파이프라인 (수직 절단)
   - 자연어 입력 → 태그 변환 → 이미지 생성 → 결과 출력, 이 한 줄을 끝까지 관통
3. 3순위 — 고급 기능
   - 이미지 퀄리티 필터링, 인페인팅 보조, 재조합 추천 등

### UI 먼저 vs 기능 먼저
- 결론: 수직 절단(Vertical Slicing) — 와이어프레임 수준의 UI 뼈대를 잡고, 핵심 파이프라인 하나를 끝까지 관통시킨 뒤 병렬 고도화
- UI 우선 근거: 조작 방식이 데이터 구조를 결정함 / UX가 핵심인 앱
- 기능 우선 근거: 기술 리스크 먼저 제거 / API 호출 가능 여부 확인
